# Merge Conflict Playbook

## 왜 충돌이 자주 났는가

최근 충돌의 핵심 원인은 다음 2가지였습니다.

1. **`app.py` 단일 파일 집중 수정**
   - 화면/상태/채팅/렌더링이 한 파일에 몰려 있어, 서로 다른 기능 작업도 같은 줄 근처를 동시에 수정하게 됩니다.

2. **줄바꿈(EOL) 불일치로 인한 대규모 diff**
   - `CRLF ↔ LF`가 섞이면 논리 변경이 거의 없어도 파일 전체가 바뀐 것처럼 보여 충돌 확률이 급격히 올라갑니다.

## 이번에 적용한 해결책

- 저장소 루트에 `.gitattributes`를 추가해 `*.py`, `*.md` 등 주요 텍스트 파일의 줄바꿈을 `LF`로 고정했습니다.
- 이 설정으로 환경이 달라도 Git 인덱스 기준 줄바꿈이 정규화되어 "전체 파일 변경" 형태의 잡음 diff를 줄일 수 있습니다.

## 권장 작업 방식

1. 기능별로 파일 경계를 나눠 작은 PR로 병합
2. 한 PR에서 `app.py`를 대규모 포맷/정렬 변경하지 않기
3. 병합 전에 `git fetch && git rebase origin/main`으로 선반영
4. 충돌 반복 구간은 helper/module로 분리해 수정 영역 격리

## 충돌 발생 시 빠른 체크리스트

- `git diff --check`로 whitespace 이슈 확인
- `git config core.autocrlf` 값 확인 (팀 표준 유지)
- 의미 없는 전체 라인 변경인지 먼저 확인 후 재정렬
